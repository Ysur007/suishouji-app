四个页面，一套语言

记录、整理、对话、我的是一级页面，共用同一个页头。桌面三栏，平板收掉一层，手机换成底部标签栏。

记录 · 当一个聊天窗口用。往上翻超过一屏，右下角浮出「最新」，点一下回到底部。

三个月后，你怎么找回来

不用记得是哪天，也不用记得当时用了哪个词。

  • 整理一次生成主题、可勾选的待办、值得回看的句子。
  • 对话答案下面挂着原文引用，点一下回到那条记录。
  • 时间线隔了多久、当天第几条、来自哪台设备。

它出现在哪一刻

它不试图成为知识库，也不做团队 Wiki。它只负责把"想到的那一秒"留下来，并在你需要的时候还给你。

  1. 09:41会议室

    想法冒出来的那一秒

    手机上发一条，标签选「工作」。回到工位打开电脑，它已经在记录流里了，不用复制粘贴，也不用等同步按钮转完。群里的共享也一样：发给「露营小队」，三台手机同时看见。

  2. 23:20床上

    不想起身开电脑

    记一句明天要做的事，锁屏。它先落在这台手机的 IndexedDB 里，网络恢复后自己补发。第二天在电脑上，它出现在昨晚那个位置，时间戳精确到分。

  3. 半年后不记得哪天

    只记得自己写过

    搜一个词，或者直接问"上次那个同步冲突的方案是怎么定的"。答案下面挂着原文引用，点一下就跳回那条记录。归纳必须能回到原文，否则它只是一段更漂亮的猜测。

它也明确不适合一些事

这些不是待办清单，是设计取舍。写在这里，省得你部署完才发现。

并发

单文件 JSON 加全量内存，适合个人和小团队。几十人同时写，该换 SQLite 或 Postgres——Op 模型不用改，只换持久化层。

加密

没有端到端加密，服务端能读到明文，data/db.json 里就是原文。别把不能外泄的东西放进来。

冲突

粒度是整条记录的后写覆盖。两个人同一秒改同一条，会丢掉其中一次。要逐字合并得换 CRDT。

三条路，选最短的那条

最快的一条是 Docker：一个服务、一个端口、一个数据目录。想改代码就走本地开发，只想用就走客户端。

Docker最省事 
git clone https://github.com/Ysur007/suishouji-app.git
cd suishouji-app && docker compose up -d

数据挂在 ./data。升级只要 git pull && docker compose up -d --build。

本地开发改代码 
npm install
npm run dev

前端 5173，同步服务 8787，Vite 已把 /api、/ws 代理过去。

客户端不折腾

Windows 安装包把前端和服务端一起打进 exe，数据在 %APPDATA%\Suishouji；Android 包把页面打包进 app，服务器地址可以随时改。

两个包都没做代码签名：Windows 首次运行会被 SmartScreen 拦（更多信息 → 仍要运行），Android 是 debug 签名，适合自用。

现在把它放到你自己的机器上。

不需要信用卡，不需要注册账号，也不需要先看一段演示视频。一条命令之后，记录就归你了。
