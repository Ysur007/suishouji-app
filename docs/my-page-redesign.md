# 「我的」页重新设计方案

> 状态：**已实施**（v1.3.0）。范围限定在 `/account` 及其入口与重叠模块，
> 数据模型、同步、鉴权、AI 存储等业务逻辑一律不动。

---

## 一、现状盘点

### 1.1 页面结构（`src/pages/AccountPage.tsx`，v1.2.7）

```
.aiHead        标题「我的」+ 已登录/已退出/未登录 + 一句说明
.acctBody
├─ 未登录 CTA 卡（仅未登录时出现）      登录 / 注册
├─ 账号卡
│   ├─ 头像 + @用户名 + 副标题
│   └─ KV：本机设备 / 我的记录 N 条 / 所在群 N 个
│   └─ 操作：退出登录（两段确认） | 回到记录
├─ 共享空间卡                            群列表 → 点了直接切到该群并跳记录页
├─ 数据卡                                清除本机缓存（登录态下 disabled + 一行小字）
├─ 服务器卡（仅 App 壳模式）              地址输入 / 保存并重载 / 恢复默认
└─ 免责声明（灰色长句）
```

### 1.2 相关但不在此页的模块

| 模块 | 位置 | 与本页的关系 |
| --- | --- | --- |
| 设置面板 `SettingsSheet` | Rail 齿轮 / 记录页右上齿轮 | **内容高度重叠**：账号行（还带一个「管理 → /account」绕回本页）、设备与平台、同步状态、在线设备、本地内容、AI 状态 + 配置、导出本机 / 导入 / 导出服务端、清空本地缓存、关于（写死 `v1.0.0`） |
| 引擎标签 `EngineTag` | 整理页 / 对话页头部 | AI 配置的唯一入口；「我的」页看不到 AI 状态 |
| 群信息 `GroupSheet` | 仅在**当前处于该群**时，记录页右上「群信息」 | 从「我的」进群就跳走了，回不到群管理 |
| 登录页 `/login` | 独立页 | 未登录时本页 CTA 指向 `?next=/account` |

### 1.3 问题清单（后面每项改动都要对上其中一条）

| 编号 | 问题 | 具体表现 |
| --- | --- | --- |
| P1 | 视觉权重扁平 | 身份、群列表、危险操作都是同一种白卡、同样圆角，看过去一样重要；「退出登录」和「回到记录」并排，主次不分 |
| P2 | 功能割裂 | 群管理要先进群再点右上角；AI 状态只在设置/引擎标签；备份导入导出在设置里；**同一件事两个入口** |
| P3 | 重复实现 | 「清除本机缓存」有两套：本页 `clearCache()`（仅未登录可用，重置 store）与设置里 `clearLocal()`（清 localStorage + IDB 并 reload）。语义不同、文案都叫清缓存 |
| P4 | 死路与误导 | 登录态下「清除本机缓存」是 disabled，用户点了没反应，只有一行 11px 小字说明；「回到记录」在 Rail / Tab 已有一级入口，纯冗余 |
| P5 | 信息过期 | 关于写死 `v1.0.0`，实际已是 `1.2.7`；版本从未随发布变过 |
| P6 | 空间利用 | 桌面 1280 下单列 760，两侧 300+ 空白；信息密度低，靠长滚动 |
| P7 | 缺失能力（v1.3.2 补了前两项） | 改密码 ✅ / 改设备名 ✅ / 踢下线（改密码时顺带作废其它 token）· 账号注销（仍未做） |
| P8 | 噪音 | 免责声明是一整段 11px 灰字，压在页面最底部当"脚注"，实际是安全说明，应该可查但不该占视线 |

## 二、目标用户与核心场景

| 用户 | 特征 | 在「我的」要什么 |
| --- | --- | --- |
| U1 个人记录者 | 手机为主，一天十几次随手记 | 几乎不进来；进来只关心「我登录了吗 / 有没有同步上」 |
| U2 多设备用户 | PC + 手机双开 | 同步是否在线、有几台在线、待发送几条、要不要重登 |
| U3 小团队 / 家庭 | 3–10 人共享群 | 群有几个、几个人、邀请谁、改名、退出群 |
| U4 自部署 / 技术型 | 自己搭服务器、常导出 | 数据在哪、怎么整包导出、服务器地址（壳模式）、引擎配置 |

**核心场景（按发生频率排序）**
1. S1 换设备 / 首次登录 → 要一个不费脑的登录入口（P1、P4）
2. S2 「我记的东西怎么没同步过来」→ 需要同步状态 + 在线设备 + 本地条数一眼可见（P2）
3. S3 管群：邀请成员、改名、退出 → 现在必须先切到那个群（P2）
4. S4 备份 / 迁移 / 清缓存 → 两套入口口径不一（P3）
5. S5 配 AI → 只在引擎标签可达（P2）
6. S6 退出登录 → 要和「清数据」明确区分（P4）

## 三、重新设计方案

### 3.1 布局与视觉方向

**一句话：从「三张同权重卡片」变成「一个身份头 + 五个功能分区」。**

```
┌─ 身份头（Identity）───────────────────────────────┐
│ [S]  @shotuser                    [已同步]        │
│      记录绑定在此账号下，各设备自动同步            │
│      3 条记录 · 1 个群 · Linux·Chrome             │
│      [退出登录]                    或  [登录/注册] │
└──────────────────────────────────────────────────┘
   分区 1  共享空间     → 行列表（群 + 管理 / 新建群）
   分区 2  数据与备份   → 导出本机 / 导出服务端 / 导入 / 清除本机缓存
   分区 3  AI 引擎      → 状态 + 模型名 + 配置
   分区 4  本机与服务   → 设备 / 同步 / 在线设备 / 服务器地址（壳）
   分区 5  关于         → 版本、数据存放、安全说明（折叠）
```

- **身份头取代「账号卡 + KV 卡」**：头像 48px、用户名 18px、状态胶囊贴右侧；副标题一行说清"这条记录属于谁、会不会同步"；主操作只留一个（登录 **或** 退出登录），不再是两个并列按钮。
- **分区用「行列表」而不是卡片**：每行 48px（移动 52px），左侧 label、右侧 value + `›`，行间 1px `--line` 分隔；分区之间 24px 空隙 + 11px 小标题。这是设置类界面的通用语法，比三张同款白卡更容易扫读。
- **危险操作下沉**：退出登录进身份头的次级位；「清除本机缓存」放到「数据与备份」最后一行，用描边按钮 + 两段确认，并且在不可用时**说明原因**而不是单纯灰掉。
- **视觉继续遵守黑白体系**（`DESIGN.md`）：不加品牌色，层级靠明度与留白；数字用 `tabular-nums` 防跳动；圆角统一 16（与 `.acctCard`、`.loginGate` 一致）。
- **桌面双列（≥1181px）**：左列 380 = 身份头 + AI 引擎 + 关于；右列 1fr = 共享空间 + 数据与备份 + 本机与服务。两列各自成组，避免 760 单列两侧留白（P6）。
  1025–1180 保持双列但收窄；≤1024 单列 720；≤720 单列全宽、行高 52、主操作通栏。

### 3.2 功能模块重组

| 新模块 | 收纳的旧内容 | 变化 |
| --- | --- | --- |
| **身份头** | 头像、@用户名、已登录/已退出/未登录、副标题、记录数/群数、设备名、同步徽标 | 合并；状态从"标题旁的小字 + 卡片内又写一遍"收敛成一个胶囊；计数并成一行 12px 灰字 |
| **共享空间** | 群列表 | 每行右侧新增「管理」→ 直接打开已有 `GroupSheet`（邀请/改名/移出/退出）；空态给「新建群」主按钮 |
| **数据与备份** | 我的页「清除本机缓存」+ 设置面板「导出本机 / 导入 / 导出服务端 / 清空本地缓存」 | **合并成一处**；四个动作同一行列表；清缓存统一为一套实现、一句文案 |
| **AI 引擎** | 设置面板 AI 行、引擎标签 | 状态（本地分析 / 模型 · xxx / 未就绪）+「配置」→ `AiSheet`；登出时显示「登录后可用」 |
| **本机与服务** | 设置面板「本机」组（设备/平台/同步/在线设备/本地内容）+ 我的页服务器卡 | 保留服务器地址（壳模式才出现）；在线设备显示名称 + 最后活跃时间 |
| **关于** | 设置面板「关于」+ 我的页免责声明 | 版本改为构建时注入的真实版本；安全说明折叠，默认只显示一行 |

### 3.3 导航与交互改进

1. **群「管理」直达**（新增入口，复用 `GroupSheet`）：解决 S3 的"必须先进群"。
   `共享空间` 行 → `管理` 按钮 `open({kind:'group', groupId})`；行主体仍是"切到该群并回记录页"，两个热区分离。
2. **AI 状态前移**：`我的` 能直接看到当前引擎与模型名，`配置` 打开 `AiSheet`；解决 S5 只能从引擎标签进。
3. **清缓存统一口径**：名称统一「清除本机缓存」，行为统一为「删本机副本（IndexedDB + 登录前的本地态），云端不动」；登录态下不隐藏也不禁用，而是**改成需要先退出登录**，点击时用 toast 说清原因（解决 P3、P4 的"点了没反应"）。
4. **退出登录两步留在原地**：第一下变「确认退出？数据会留在本机」，4 秒回退（沿用现有实现，不引入新弹层）。
5. **分区锚点（桌面可选）**：≥1181 时左列顶部固定一个分区目录（共享 / 数据 / 引擎 / 本机 / 关于），点击滚动定位；≤1180 不显示（内容不长，反而多一层噪音）。
6. **键盘可达**：行列表用 `<button>` 语义，`Tab` 顺序 = 视觉顺序，`Enter` 触发，`Esc` 关弹层（沿用现有 `Sheet` 行为）。

### 3.4 新增 / 删除清单（含理由）

**新增**

| 项 | 理由 | 实现成本 |
| --- | --- | --- |
| 共享空间每行「管理」 | 群管理原本要先进群（P2 / S3） | 复用 `GroupSheet`，一个按钮 |
| AI 引擎分区 | 引擎状态与配置在「我的」不可见（P2 / S5） | 复用 `AiSheet` + `useAi.status` |
| 真实版本号 | 关于写死 v1.0.0（P5） | `vite.config.ts` 注入 `__APP_VERSION__` |
| 桌面双列 + 分区目录 | 760 单列两侧留白（P6） | 纯 CSS + 少量结构 |
| 在线设备行（名称 + 最后活跃） | 排查同步要"有几台在线"（S2） | 数据已在 `sync.peers` |

**删除**

| 项 | 理由 |
| --- | --- |
| 「回到记录」按钮 | Rail / TabBar 已有一级入口，与"退出登录"并列属于同级干扰（P1、P4） |
| 设置面板的「账号」整行 | 与身份头重复，且它的「管理」按钮绕回本页（P1、P3） |
| 设置面板的「清空本地缓存」 | 与本页清缓存是两套实现、两种语义（P3） |
| 设置面板的「本机」组与「关于」 | 移到「我的」，设置只留应用级偏好（导出导入也一并移走） |
| 我的页标题旁的「已登录」小字 | 与身份头胶囊重复（P1） |
| 我的页底部整段免责声明 | 收进「关于」折叠，信息不丢、视线不挡（P8） |

**明确不动**（业务边界）：登录/注册与 token 流程、退出登录不清数据、`clearCache` 的语义、群与空间模型、`GroupSheet` 的邀请/改名/移出/退出逻辑、AI 配置的按账号存储与服务端调用、服务器地址覆盖与重载。

### 3.5 双端适配

| 宽度 | 布局 |
| --- | --- |
| ≥ 1181px | 左 240 目录 + 右内容双列（左列 380 / 右列 1fr），内容最大宽 1100 |
| 1025–1180px | 双列，目录收起，内容 900 |
| ≤ 1024px | 单列 720，目录隐藏 |
| ≤ 720px | 单列全宽；行高 52；身份头主操作通栏；分区标题 sticky；`padding-bottom` 预留 TabBar + 安全区 |

移动端不引入二级导航：所有分区就在一页里，向下滚动即可（与「整理」页的报告分区一致）。

## 五、实施记录（v1.3.0）

按上面方案落地时，有两处按实际情况调整，其余照做：

1. **分区目录没做**（原计划「≥1181px 左列固定分区目录」）。双列布局本身已经把宽度吃满，
   再加一列目录等于第三层导航（Rail → 目录 → 内容），与「每层只回答一个问题」冲突。
   桌面改为：左列放「身份头 / AI 引擎 / 关于」，右列放「共享空间 / 数据与备份 / 本机与服务」。
2. **设置面板整块删除**，不只是删三行。内容全部迁进「我的」之后它已经空了，
   与其留一个只有「完成」按钮的抽屉，不如去掉；Rail 底部齿轮、记录页/空间页/时间线页顶栏的齿轮一并移除
   （`我的` 在 Rail 和 TabBar 都有一级入口）。`{kind:'settings'}` 从 `ui.ts` 与 `SheetHost` 移除。

其他落地点：
- 版本号由 `vite.config.ts` 从 `package.json` 注入（`__APP_VERSION__`），「关于」显示 v1.3.0，不再写死；
- 窄屏分区顺序用 `.acctCol { display: contents }` + `order` 重排成
  身份头 → 共享 → 数据 → 本机 → AI → 关于，桌面仍是两列；
- 行右侧的 `›` 只给「会跳走 / 打开面板」的行，纯动作（导出、导入、清除）不给箭头；
- 清除缓存只剩 `clearCache()` 一套实现，登录态点击会提示「先退出登录」，不再灰掉不说话；
- 验收：1280 双列 380+678、1024 单列 760、390 单列 358 无横向滚动；14 行全部可点；
  管群打开 GroupSheet、导出触发下载、退出两段确认、登出后 AI 行显示「登录」。

## 七、补上 P7 的两项账号能力（v1.3.2）

「我的」有了账号语义，却只能看和退出，连密码都改不了。补两个小浮层：

| 能力 | 入口 | 端 | 规则 |
| --- | --- | --- | --- |
| 修改密码 | 本机与服务 → 「修改密码」 | `POST /api/auth/password` | 校验原密码；新密码 ≥6 位且不能与原密码相同；换新盐重算 scrypt 哈希；**作废该账号其它设备上的 token**，只留当前这台 |
| 设备名称 | 本机与服务 → 设备行「改名」 | `store.setDeviceName` + `sync.restart()` | 只改本机标识（`ssj:device`，≤24 字），重新握手后其他设备的「在线设备」立刻看到新名字；不影响数据归属 |

- 「改密码顺手踢掉其它设备」是刻意的：密码泄露后只改不改 token，等于没改。
- 设备改名走 `sync.restart()`（公开方法）而不是自造一条 op：名字是连接握手带的元信息，不是记录。
- 未登录时两行都显示「登录」，点了回 `/login?next=/account`。
- 验收：原密码错 / 新密码太短 / 与原密码相同 各返回 400 文案；成功后旧 token 200、另一台 401、旧密码登录 401、新密码登录 200；
  UI 侧改名后 `ssj:device` 变了、刷新仍是新名字、toast「设备名已更新」。
