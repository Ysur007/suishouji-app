# 「我的」页重新设计方案

> 状态：**已实施**（v1.3.0）。范围限定在 `/account` 及其入口与重叠模块，
> 数据模型、同步、鉴权、AI 存储等业务逻辑一律不动。

---

## 一、现状盘点

### 1.1 页面结构（`src/pages/AccountPage.tsx`，v1.2.7）

```
.aiHead        标题「我的」+ 已登录/已退出/未登录 + 一句说明
.acctBody
├─ 未登录 CTA 卡（仅未登录时出现）      登录 / 注册
├─ 账号卡
│   ├─ 头像 + @用户名 + 副标题
│   └─ KV：本机设备 / 我的记录 N 条 / 所在群 N 个
│   └─ 操作：退出登录（两段确认） | 回到记录
├─ 共享空间卡                            群列表 → 点了直接切到该群并跳记录页
├─ 数据卡                                清除本机缓存（登录态下 disabled + 一行小字）
├─ 服务器卡（仅 App 壳模式）              地址输入 / 保存并重载 / 恢复默认
└─ 免责声明（灰色长句）
```

### 1.2 相关但不在此页的模块

| 模块 | 位置 | 与本页的关系 |
| --- | --- | --- |
| 设置面板 `SettingsSheet` | Rail 齿轮 / 记录页右上齿轮 | **内容高度重叠**：账号行（还带一个「管理 → /account」绕回本页）、设备与平台、同步状态、在线设备、本地内容、AI 状态 + 配置、导出本机 / 导入 / 导出服务端、清空本地缓存、关于（写死 `v1.0.0`） |
| 引擎标签 `EngineTag` | 整理页 / 对话页头部 | AI 配置的唯一入口；「我的」页看不到 AI 状态 |
| 群信息 `GroupSheet` | 仅在**当前处于该群**时，记录页右上「群信息」 | 从「我的」进群就跳走了，回不到群管理 |
| 登录页 `/login` | 独立页 | 未登录时本页 CTA 指向 `?next=/account` |

### 1.3 问题清单（后面每项改动都要对上其中一条）

| 编号 | 问题 | 具体表现 |
| --- | --- | --- |
| P1 | 视觉权重扁平 | 身份、群列表、危险操作都是同一种白卡、同样圆角，看过去一样重要；「退出登录」和「回到记录」并排，主次不分 |
| P2 | 功能割裂 | 群管理要先进群再点右上角；AI 状态只在设置/引擎标签；备份导入导出在设置里；**同一件事两个入口** |
| P3 | 重复实现 | 「清除本机缓存」有两套：本页 `clearCache()`（仅未登录可用，重置 store）与设置里 `clearLocal()`（清 localStorage + IDB 并 reload）。语义不同、文案都叫清缓存 |
| P4 | 死路与误导 | 登录态下「清除本机缓存」是 disabled，用户点了没反应，只有一行 11px 小字说明；「回到记录」在 Rail / Tab 已有一级入口，纯冗余 |
| P5 | 信息过期 | 关于写死 `v1.0.0`，实际已是 `1.2.7`；版本从未随发布变过 |
| P6 | 空间利用 | 桌面 1280 下单列 760，两侧 300+ 空白；信息密度低，靠长滚动 |
| P7 | 缺失能力（v1.3.2 补了前两项） | 改密码 ✅ / 改设备名 ✅ / 踢下线（改密码时顺带作废其它 token）· 账号注销（仍未做） |
| P8 | 噪音 | 免责声明是一整段 11px 灰字，压在页面最底部当"脚注"，实际是安全说明，应该可查但不该占视线 |

## 二、目标用户与核心场景

| 用户 | 特征 | 在「我的」要什么 |
| --- | --- | --- |
| U1 个人记录者 | 手机为主，一天十几次随手记 | 几乎不进来；进来只关心「我登录了吗 / 有没有同步上」 |
| U2 多设备用户 | PC + 手机双开 | 同步是否在线、有几台在线、待发送几条、要不要重登 |
| U3 小团队 / 家庭 | 3–10 人共享群 | 群有几个、几个人、邀请谁、改名、退出群 |
| U4 自部署 / 技术型 | 自己搭服务器、常导出 | 数据在哪、怎么整包导出、服务器地址（壳模式）、引擎配置 |

**核心场景（按发生频率排序）**
1. S1 换设备 / 首次登录 → 要一个不费脑的登录入口（P1、P4）
2. S2 「我记的东西怎么没同步过来」→ 需要同步状态 + 在线设备 + 本地条数一眼可见（P2）
3. S3 管群：邀请成员、改名、退出 → 现在必须先切到那个群（P2）
4. S4 备份 / 迁移 / 清缓存 → 两套入口口径不一（P3）
5. S5 配 AI → 只在引擎标签可达（P2）
6. S6 退出登录 → 要和「清数据」明确区分（P4）

## 三、重新设计方案

### 3.1 布局与视觉方向

**一句话：从「三张同权重卡片」变成「一个身份头 + 五个功能分区」。**

```
┌─ 身份头（Identity）───────────────────────────────┐
│ [S]  @shotuser                    [已同步]        │
│      记录绑定在此账号下，各设备自动同步            │
│      3 条记录 · 1 个群 · Linux·Chrome             │
│      [退出登录]                    或  [登录/注册] │
└──────────────────────────────────────────────────┘
   分区 1  共享空间     → 行列表（群 + 管理 / 新建群）
   分区 2  数据与备份   → 导出本机 / 导出服务端 / 导入 / 清除本机缓存
   分区 3  AI 引擎      → 状态 + 模型名 + 配置
   分区 4  本机与服务   → 设备 / 同步 / 在线设备 / 服务器地址（壳）
   分区 5  关于         → 版本、数据存放、安全说明（折叠）
```

- **身份头取代「账号卡 + KV 卡」**：头像 48px、用户名 18px、状态胶囊贴右侧；副标题一行说清"这条记录属于谁、会不会同步"；主操作只留一个（登录 **或** 退出登录），不再是两个并列按钮。
- **分区用「行列表」而不是卡片**：每行 48px（移动 52px），左侧 label、右侧 value + `›`，行间 1px `--line` 分隔；分区之间 24px 空隙 + 11px 小标题。这是设置类界面的通用语法，比三张同款白卡更容易扫读。
- **危险操作下沉**：退出登录进身份头的次级位；「清除本机缓存」放到「数据与备份」最后一行，用描边按钮 + 两段确认，并且在不可用时**说明原因**而不是单纯灰掉。
- **视觉继续遵守黑白体系**（`DESIGN.md`）：不加品牌色，层级靠明度与留白；数字用 `tabular-nums` 防跳动；圆角统一 16（与 `.acctCard`、`.loginGate` 一致）。
- **桌面双列（≥1181px）**：左列 380 = 身份头 + AI 引擎 + 关于；右列 1fr = 共享空间 + 数据与备份 + 本机与服务。两列各自成组，避免 760 单列两侧留白（P6）。
  1025–1180 保持双列但收窄；≤1024 单列 720；≤720 单列全宽、行高 52、主操作通栏。

### 3.2 功能模块重组

| 新模块 | 收纳的旧内容 | 变化 |
| --- | --- | --- |
| **身份头** | 头像、@用户名、已登录/已退出/未登录、副标题、记录数/群数、设备名、同步徽标 | 合并；状态从"标题旁的小字 + 卡片内又写一遍"收敛成一个胶囊；计数并成一行 12px 灰字 |
| **共享空间** | 群列表 | 每行右侧新增「管理」→ 直接打开已有 `GroupSheet`（邀请/改名/移出/退出）；空态给「新建群」主按钮 |
| **数据与备份** | 我的页「清除本机缓存」+ 设置面板「导出本机 / 导入 / 导出服务端 / 清空本地缓存」 | **合并成一处**；四个动作同一行列表；清缓存统一为一套实现、一句文案 |
| **AI 引擎** | 设置面板 AI 行、引擎标签 | 状态（本地分析 / 模型 · xxx / 未就绪）+「配置」→ `AiSheet`；登出时显示「登录后可用」 |
| **本机与服务** | 设置面板「本机」组（设备/平台/同步/在线设备/本地内容）+ 我的页服务器卡 | 保留服务器地址（壳模式才出现）；在线设备显示名称 + 最后活跃时间 |
| **关于** | 设置面板「关于」+ 我的页免责声明 | 版本改为构建时注入的真实版本；安全说明折叠，默认只显示一行 |

### 3.3 导航与交互改进

1. **群「管理」直达**（新增入口，复用 `GroupSheet`）：解决 S3 的"必须先进群"。
   `共享空间` 行 → `管理` 按钮 `open({kind:'group', groupId})`；行主体仍是"切到该群并回记录页"，两个热区分离。
2. **AI 状态前移**：`我的` 能直接看到当前引擎与模型名，`配置` 打开 `AiSheet`；解决 S5 只能从引擎标签进。
3. **清缓存统一口径**：名称统一「清除本机缓存」，行为统一为「删本机副本（IndexedDB + 登录前的本地态），云端不动」；登录态下不隐藏也不禁用，而是**改成需要先退出登录**，点击时用 toast 说清原因（解决 P3、P4 的"点了没反应"）。
4. **退出登录两步留在原地**：第一下变「确认退出？数据会留在本机」，4 秒回退（沿用现有实现，不引入新弹层）。
5. **分区锚点（桌面可选）**：≥1181 时左列顶部固定一个分区目录（共享 / 数据 / 引擎 / 本机 / 关于），点击滚动定位；≤1180 不显示（内容不长，反而多一层噪音）。
6. **键盘可达**：行列表用 `<button>` 语义，`Tab` 顺序 = 视觉顺序，`Enter` 触发，`Esc` 关弹层（沿用现有 `Sheet` 行为）。

### 3.4 新增 / 删除清单（含理由）

**新增**

| 项 | 理由 | 实现成本 |
| --- | --- | --- |
| 共享空间每行「管理」 | 群管理原本要先进群（P2 / S3） | 复用 `GroupSheet`，一个按钮 |
| AI 引擎分区 | 引擎状态与配置在「我的」不可见（P2 / S5） | 复用 `AiSheet` + `useAi.status` |
| 真实版本号 | 关于写死 v1.0.0（P5） | `vite.config.ts` 注入 `__APP_VERSION__` |
| 桌面双列 + 分区目录 | 760 单列两侧留白（P6） | 纯 CSS + 少量结构 |
| 在线设备行（名称 + 最后活跃） | 排查同步要"有几台在线"（S2） | 数据已在 `sync.peers` |

**删除**

| 项 | 理由 |
| --- | --- |
| 「回到记录」按钮 | Rail / TabBar 已有一级入口，与"退出登录"并列属于同级干扰（P1、P4） |
| 设置面板的「账号」整行 | 与身份头重复，且它的「管理」按钮绕回本页（P1、P3） |
| 设置面板的「清空本地缓存」 | 与本页清缓存是两套实现、两种语义（P3） |
| 设置面板的「本机」组与「关于」 | 移到「我的」，设置只留应用级偏好（导出导入也一并移走） |
| 我的页标题旁的「已登录」小字 | 与身份头胶囊重复（P1） |
| 我的页底部整段免责声明 | 收进「关于」折叠，信息不丢、视线不挡（P8） |

**明确不动**（业务边界）：登录/注册与 token 流程、退出登录不清数据、`clearCache` 的语义、群与空间模型、`GroupSheet` 的邀请/改名/移出/退出逻辑、AI 配置的按账号存储与服务端调用、服务器地址覆盖与重载。

### 3.5 双端适配

| 宽度 | 布局 |
| --- | --- |
| ≥ 1181px | 左 240 目录 + 右内容双列（左列 380 / 右列 1fr），内容最大宽 1100 |
| 1025–1180px | 双列，目录收起，内容 900 |
| ≤ 1024px | 单列 720，目录隐藏 |
| ≤ 720px | 单列全宽；行高 52；身份头主操作通栏；分区标题 sticky；`padding-bottom` 预留 TabBar + 安全区 |

移动端不引入二级导航：所有分区就在一页里，向下滚动即可（与「整理」页的报告分区一致）。

### 3.6 验收标准

- 390×844：无横向滚动；分区标题吸顶；「退出登录」两段确认；点群「管理」打开 `GroupSheet`；清缓存不可用时 toast 说明原因。
- 1280×860：双列不重叠，左列起始与标题对齐；版本号 = `package.json` 的 `1.2.7`。
- 键盘 Tab 顺序与视觉顺序一致；Esc 关闭任何弹层。
- 未登录态：身份头显示「未登录」+ 主按钮「登录 / 注册」；共享空间与 AI 分区显示"登录后可用"而不是空表。

## 五、实施记录（v1.3.0）

按上面方案落地时，有两处按实际情况调整，其余照做：

1. **分区目录**：第一版判断「双列已吃满宽度、再加目录是第三层导航」而砍掉，但实际看下来
   `我的` 与记录 / 整理 / 对话相比少了一层骨架，切过去像换了结构。v1.3.3 补回：
   `SidePanel` 增加 `AccountPanel`（账号只展示 + 分区目录），点击滚到对应分区、选中反白；
   **不做滚动联动**——两列并排时同一屏会露出五六个分区，「当前在哪一段」没有唯一答案。
2. **设置面板整块删除**，不只是删三行。内容全部迁进「我的」之后它已经空了，
   与其留一个只有「完成」按钮的抽屉，不如去掉；Rail 底部齿轮、记录页/空间页/时间线页顶栏的齿轮一并移除
   （`我的` 在 Rail 和 TabBar 都有一级入口）。`{kind:'settings'}` 从 `ui.ts` 与 `SheetHost` 移除。

其他落地点：
- 版本号由 `vite.config.ts` 从 `package.json` 注入（`__APP_VERSION__`），「关于」显示 v1.3.0，不再写死；
- 窄屏分区顺序用 `.acctCol { display: contents }` + `order` 重排成
  身份头 → 共享 → 数据 → 本机 → AI → 关于，桌面仍是两列；
- 行右侧的 `›` 只给「会跳走 / 打开面板」的行，纯动作（导出、导入、清除）不给箭头；
- 清除缓存只剩 `clearCache()` 一套实现，登录态点击会提示「先退出登录」，不再灰掉不说话；
- 验收：1280 双列 380+678、1024 单列 760、390 单列 358 无横向滚动；14 行全部可点；
  管群打开 GroupSheet、导出触发下载、退出两段确认、登出后 AI 行显示「登录」。

## 六、左列空白补位：概览 + 最近记录（v1.3.1）

首版落地后左列（身份头 / AI / 关于）明显比右列短，宽屏上有大片留白。补两块**结构与其他页面一致**的内容：

| 模块 | 复用的口径 | 字段 | 数据来源 |
| --- | --- | --- | --- |
| 概览（4 格） | 整理页 `.orgStats` / `.stat`：24px 数字 + 11px 标签、1px 分隔线 | 条记录 / 个文件夹 / 个群 / 台在线 | `liveMemos(memos)`、`folders`（未删）、`groups`、`sync.peers` |

  同源同值——三个地方不会互相矛盾。

- 窄屏：概览从 4 列改 2×2（380px→358px 放四列会挤成 70px 一格），顺序插在身份头之后、共享空间之前。

## 七、补上 P7 的两项账号能力（v1.3.2）

「我的」有了账号语义，却只能看和退出，连密码都改不了。补两个小浮层：

| 能力 | 入口 | 端 | 规则 |
| --- | --- | --- | --- |
| 修改密码 | 本机与服务 → 「修改密码」 | `POST /api/auth/password` | 校验原密码；新密码 ≥6 位且不能与原密码相同；换新盐重算 scrypt 哈希；**作废该账号其它设备上的 token**，只留当前这台 |
| 设备名称 | 本机与服务 → 设备行「改名」 | `store.setDeviceName` + `sync.restart()` | 只改本机标识（`ssj:device`，≤24 字），重新握手后其他设备的「在线设备」立刻看到新名字；不影响数据归属 |

- 「改密码顺手踢掉其它设备」是刻意的：密码泄露后只改不改 token，等于没改。
- 设备改名走 `sync.restart()`（公开方法）而不是自造一条 op：名字是连接握手带的元信息，不是记录。
- 未登录时两行都显示「登录」，点了回 `/login?next=/account`。
- 验收：原密码错 / 新密码太短 / 与原密码相同 各返回 400 文案；成功后旧 token 200、另一台 401、旧密码登录 401、新密码登录 200；
  UI 侧改名后 `ssj:device` 变了、刷新仍是新名字、toast「设备名已更新」。

## 八、把二级面板补回来（v1.3.3）

起因：`我的` 是唯一没有中间面板的一级页面，和记录 / 整理 / 对话并排切着看时骨架不齐；
面板补回后，标题也与内容左边缘对齐了（之前标题在 gutter、卡片在 760 居中，错开 100px）。

- `src/lib/acctnav.ts`：分区清单（id + 中文名）+ 一个极小的 zustand store（`active` / `goTo`）。
- `SidePanel` 新增 `AccountPanel`：`PanelHead「我的 · N 条」` → 「账号」区块（@用户名 + 一句说明，只展示）
  → 「分区」目录（七行，每行带图标，选中反白，与记录页面板的选中语言一致）。
- `AccountPage`：给各分区加 `id`；订阅 `request`，点击时 `scrollIntoView`。
- 行为约定：**只做「点击跳转 + 记住点了哪项」，不做滚动高亮**。理由写在 `acctnav.ts` 顶部：
  内容是两个并排的列，一屏能同时看到五六个分区，滚动高亮只会来回跳（试过 IO 与「最近锚点」两种判定，
  都不稳定：内容不满一屏时点「关于」会被立刻改回上一个分区）。
- 窄屏（≤1024）面板隐藏，页面仍是单列滚动，不引入第二套导航；
  单列时两个 `.acctCol` 用 `display: contents` 打散，按 `order` 重排成
  身份头 → 概览 → 共享 → 数据 → 本机 → 最近 → AI → 关于（宽屏仍是两列，`order` 不生效）。

## 九、左面板 = 三个常用操作（v1.3.4）

反馈：布局在为设计而设计，缺少使用逻辑——「退出登录」在身份头、「导出」在数据区、「修改密码」在本机区，
三个动作散落在需要往下滚的位置，而左面板只在做目录。

改成：**左面板按「账号 → 操作 → 分区」三段**，操作区固定三行，顺序按使用频率排。

| 顺序 | 操作 | 为什么排在这 | 交互 |
| --- | --- | --- | --- |
| 1 | 导出备份 | 换设备 / 迁移 / 备份时最常用，且没有风险 | 直接下载本机 JSON（`lib/backup.ts`） |
| 2 | 修改密码 | 偶尔用；改完会踢掉其它设备 | 打开 `PasswordBody` 浮层 |
| 3 | 退出登录 | 最少用且不可逆（记录仍在，但要重新登录） | 两段确认：整行反白变「确认退出？」，4 秒回退 |

配套的减法（避免同一动作两处出现）：
- 身份头不再带「退出登录」按钮，只显示身份与状态（宽屏）；
- 「数据与备份」在宽屏只留 导出服务端 / 从备份导入 / 清除缓存——**服务端整包导出**需要登录、是迁移用的低频动作，留在详情区；
- 「本机与服务」在宽屏不再有「修改密码」行；
- 以上三处在 ≤1024（面板隐藏）时仍然显示，用 `.acct-mobileOnly` 控制，手机上不会失去入口。

- 导出逻辑抽到 `src/lib/backup.ts`（`exportLocalBackup` / `exportServerBackup`），面板与内容区共用一份实现。
- 未登录时操作区只有「导出备份」+「登录 / 注册」；登录后换成三项。
- 验收：宽屏三项只在面板出现（内容区对应元素 `display:none`）；面板导出能触发下载、改密码能开浮层、
  退出两段确认后身份变「已退出」且操作区只剩导出 + 登录；手机上面板隐藏、三项在内容区可见。

## 十、删掉左面板的「分区目录」（v1.3.5）

上一版把三个操作收进面板后，面板变成「账号 / 操作 / 分区目录」三段。分区目录被指出是多余的一层：

- **它不承载决策**：七项就是右侧分区的名字，点过去只是滚动——而右侧本来就是两列并排，一屏能看到五六个分区，
  滚到哪一段也没有唯一答案（v1.3.3 已因此放弃滚动高亮）。
- **它挤占真动作**：目录占掉面板 2/3 的高度，把「导出 / 改密码 / 退出」推到视觉上更靠上的位置，
  但用户眼里两者都是「一行一行可点」，反而分不清哪些是真操作。

改动：`SidePanel` 的 `AccountPanel` 只留「账号 + 操作」两段；`src/lib/acctnav.ts`、
分区的 `id` 锚点、`.panel__row--nav` / `.panel__nameRow` 样式一并删除（没有使用者）。

结果：面板从「目录 + 动作」变成一块**动作栏**——上面是身份，下面是三个能立刻做成的事，中间留白不填。
留白是有意的：面板不需要被填满，缺内容时宁可空着。

## 十一、后续建议（按优先级，均未实施）

判断标准：**这条改动会不会改变用户的下一步动作**。只是让页面"看起来更完整"的，一律不做。

### P1 · 值得下一次迭代就做

**1）危险动作统一「确认条」**
- 用途：清缓存、退出登录现在是"按钮文字变成确认"，不说明后果；共用一台电脑时，用户不知道自己点下去会发生什么。
- 影响：抽一个 `ConfirmRow`（行下方展开一行说明 + 取消 / 确认），改 3 处（清缓存、退出登录、群退出）；
  不动业务逻辑，只是把 `data-confirm` 换成展开层。风险低，改动集中在 `AccountPage` + `GroupSheet`。
- 收益：所有不可逆操作有一致的"先说后果再执行"。

**2）「退出并清除本机缓存」合并成一个动作**
- 用途：换设备 / 共用电脑的真实路径是"退登 + 清本机"，现在要退出、再回来点清除、再确认。
- 影响：退出确认条里给两个选项（只退出 / 退出并清除本机）；复用 `clearCache()`。
  注意顺序：先 `signOut()` 再 `clearCache()`（后者要求未登录）。风险低。

**3）在线设备可单独下线**
- 用途：手机丢了、在网吧登录过——现在唯一手段是改密码，会把自己也踢掉。
- 影响：服务端 `tokens` 目前只存 `userId + createdAt`，要先把握手时的 `name` 落库；
  再加 `GET /api/auth/devices` 与 `POST /api/auth/devices/revoke`；「在线设备」行展开成列表。
  改动跨前后端，属于本轮之后最大的一个功能增量。

**4）同步状态补「最后同步时间」**
- 用途：「已同步」只说明连接在，不说明数据新旧；排查"怎么没同步过来"时这是第一个要看的数。
- 影响：`sync.lastAt` 已在 store 里，只需在「同步状态」行补一句 `relativeTime(sync.lastAt)`。几乎零成本。

### P2 · 有价值但不急

**5）导出支持范围**
- 用途：整包 JSON 适合迁移，但"把这个群 / 最近 30 天导出给同事"更常见。
- 影响：`/api/export` 加 `spaceId` / `days` 参数，面板"导出备份"变成一个小浮层（全部 / 本群 / 近 30 天）。
  服务端已有 `memosFor` 的过滤能力，复用即可。

**6）手机端把「关于」折叠**
- 用途：手机上是 8 个分区一条长滚动，而"数据存在哪 / 安全说明"是读一次就够的内容。
- 影响：`关于` 分区改成两行摘要 + 「展开」，或整体收进一个 `AboutSheet`。纯前端。

**7）最近记录补「查看全部」**
- 用途：只显示 3 条，想看第 4 条得切到记录页再找。
- 影响：分区标题右侧加一个「全部 n 条 →」跳到 `/`。一行代码级别。

### P3 · 先攒需求，别现在做

**8）账号注销**
- 用途：真要离开时，需要一个"把我的东西删掉"的出口。
- 影响：要先定三条规则——记录是否物理删除、群里的副本怎么处理、是否需要冷静期；
  涉及 `users / tokens / records / groups.members` 四处数据，误删不可逆。规则没定之前不动。

**9）概览加趋势（最近 7 天 / 30 天）**
- 用途：现在是静态快照，"99 条"说明不了活跃度。
- 影响：纯前端可算（`memos` 里有 `createdAt`），但会让概览从"4 个数字"变成"4 个数字 + 趋势"，
  信息密度上升；先等真实使用反馈再决定要不要加。

### 明确不做的

- 面板填满/加装饰：留白本身就是状态。
- 分区目录回归：已经证明它不承载决策。
- 大屏数据可视化、头像上传、主题切换：与"随手记"的定位无关，属于设计冲动。

## 十二、P1 落地记录（v1.3.6）

按第十一节清单，先做了 1 / 2 / 4 / 3 四项（顺序：先统一确认方式，再合并动作，再补信息，最后做跨前后端的设备下线）。

### 1）危险动作统一为「行内确认条」

- 新增 `src/components/ConfirmBar.tsx`：说明文字 + `取消 / 确认`（可带一个附加动作），只在行下面展开，不弹浮层。
- 替换了原来的"按钮文字变成确认"（`data-confirm` + 4 秒超时）：`退出登录`（面板与窄屏身份头）和
  `清除本机缓存` 现在都是"先说后果，再给两个对称出口"。
- 面板宽度只有 272px，`ConfirmBar` 在里面改成纵向按钮（`.panel .confirmBar`）。

### 2）「退出并清除本机」合并成一步

- 登录态点「清除本机缓存」→ 确认条文案写明"退出登录并清除本机副本"，确认按钮叫「退出并清除」。
- 顺序是先 `signOut()` 再 `clearCache()`（后者要求未登录）；未登录时只有一个「清除」。
- 效果：换设备/共用电脑从"退出 → 回来 → 点清除 → 再确认"变成两次点击。

### 4）同步状态补「最后同步时间」

- `已连接，改动实时推送 · 最后同步 刚刚`，用 `sync.lastAt` + `relativeTime()`。
- 排查"怎么没同步过来"时，这比一个静态的「已同步」有用。

### 3）在线设备可单独下线

- 服务端 `TokenRow` 增加 `id / name / platform / clientId / lastSeenAt`；WS 握手时 `touchToken()` 写入。
- 新接口：`GET /api/devices`（只回短 id，不下发 token）、`POST /api/devices/revoke`（当前设备不能踢）。
- 下线时只断开那台设备的 WS 连接（`SocketMeta` 里存了 token），并给它发一条 `unauthorized`。
- 客户端 `DevicesSheet.tsx`：设备名 + 平台 + 相对活跃时间，当前设备打「本机」标且不给下线按钮；
  非当前设备「下线」→ 二次确认 → 列表刷新。
- 验收：两台设备分别握手后列表两条并标出本机；下线另一台后它的 `/api/auth/me` 变 401、当前设备仍 200；
  对自己点下线返回「这台设备不能下线」。
